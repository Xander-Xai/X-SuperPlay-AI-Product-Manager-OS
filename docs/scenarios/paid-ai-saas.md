# AI SaaS 订阅与可靠交付

> 场景设计状态：DESIGNED_NOT_RUN / HUMAN_UNASSESSED。不能把合成演练当真实用户或生产验收。

## 最小问题与反证

基于公开/合成资料，写一个真实可观察的用户任务。先比较人工/规则/现成平台方案，说明什么证据会让你放弃新建应用。场景常见失败：计费幂等、取消、退款、成本翻倍、隐私删除。

## 按需知识路由

首选节点：`PM03`（访谈与行为证据）、`BIZ01`（Buyer/采购/价值与定价）、`BIZ02`（单位经济/CAC/LTV/现金流）、`BIZ03`（支付/订阅/计费需求设计）、`ENG06`（AuthN/AuthZ/多租户隔离）、`ENG04`（SQL/事务/迁移）、`AI13`（模型选型/推理与成本）、`OPS03`（容量/压测/成本上限）、`OPS04`（备份/恢复/事故响应）、`OPS05`（数据隐私/合规/删除与审计）。

不要一口气全学；先找导致失败的**一个**节点，按直接依赖回溯未掌握基础。运行：
```bash
python tools/learning_router.py scenario paid-ai-saas
python tools/learning_router.py route PM03
```

## 实验协议

1. **需求基线**：用户、使用者和买方、权限、当前替代、成本和停止条件。无买方证明写 UNKNOWN。
2. **前测**：关闭 AI 绘制最短工作链或行为流，并预测至少两个失败点。
3. **学习**：只读本次节点的权威资料 1–2 篇，解释如何改变产品/工程决策；参考 [知识手册](../atlas/knowledge-handbook.md)。
4. **最小实践**：构建公开/合成样本与 Mock API/Mock 工具，对同一任务做 NO_AI/规则基线和需要时的 AI 对照。
5. **测试**：一条成功用例 + 两条与场景相关的失败/安全负例，预注册指标与分母；提交输出与 commit，而非只描述结果。
6. **闭卷**：关闭 AI 独立修一个陌生输入/状态错误；1/3/7 天换约束复测。
7. **Go/Stop**：记录技术门禁/用户验证/商业证据，不能越权使用真实客户资料。

**最低验收**：账单/数据隔离与成本控制的合成测试，无付费证明不得商业升级。完整上线必须另经过 [生产 Gate](../launch/production-readiness.md)。
