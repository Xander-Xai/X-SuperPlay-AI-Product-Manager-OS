# 04 产品设计：PRD、用户体验、原型与验收

### 必学
- MRD（市场问题）与 PRD（需求行为）的区别；敏捷 PRD 是共识载体，不是一次写死的长规格。
- 用户故事、任务流/服务蓝图、信息架构、Figma/纸面线框和可用性测试。
- 正常态、空态、等待态、失败态、拒答、人工接管、无权限、撤销操作。
- AI 特有信任设计：出处与证据、可纠错性、模型不确定性、用户可控。
- Given/When/Then UAT；性能、成本、合规、可访问性等非功能要求。

### 实操
用 [PRD Lite](../templates/PRD.md) 写目标用户、价值、非目标、主流程和至少两条失败分支；画低保真页面，写三条可测试验收标准。若未做真实用户测试则称“原型/模拟反馈”，不宣称体验已被验证。

参照 [Atlassian PRD](https://www.atlassian.com/agile/product-management/requirements) 和 [Google PAIR](https://pair.withgoogle.com/guidebook-v2/)。
